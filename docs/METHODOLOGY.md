# Evaluation methodology

**Decision time:** immediately before a planned phone call. Communication channel and calendar context are assumed known. Prior-campaign counts and outcome refer to the earlier campaign. Current-campaign contact count is excluded because its definition includes the current contact. Duration is excluded because it is only known after the call. Macroeconomic variables are excluded rather than assuming their release timing. Names, contact details, age, marital status and default are not used. These exclusions do not establish demographic fairness; no fairness audit was performed.

**Data:** 41,188 genuine UCI Bank Marketing additional-full observations in original chronological row order. Training rows 1–24,712; validation 24,713–32,950; test 32,951–41,188. Exact customer IDs and dates are absent. Repeated contacts may cross partitions; this cannot be ruled out.

**Preprocessing:** OneHotEncoder(handle_unknown='ignore') on eight categorical columns; StandardScaler on previous/pdays. Literal 'unknown' categories remain distinct values. pdays=999 retains its documented never-contacted sentinel interpretation; this simple linear representation is a limitation. Encoders, scaler, intercept and Logistic Regression weights fit training only. Fixed C=1, no class weighting, max_iter=2000, seed 474. Validation is reported as a diagnostic; no test-driven hyperparameter selection. Exported coefficients score directly in TypeScript. 256 Python probability references are verified at absolute tolerance 1e-12 in Vitest; Python export parity is checked over the entire test partition.

**Comparison pool:** 500 records sampled with pandas random_state=474 from the untouched test partition, sorted by original index. This fixed pool is stored in D1. A documented Fisher–Yates shuffle with a 32-bit linear congruential generator (1664525*x+1013904223 mod 2^32) selects the requested count using its run seed. Labels do not enter selection. Every participating provider sees precisely the same requested input IDs. Provider adapters see only an input ID and allowlisted features.

**Limits:** 1–100 records offline; live providers default to at most 20, with a server-controlled cap. This also keeps durable step counts conservative: at most 702 steps for three offline models. The full statistical benchmark is separate and uses all 8,238 test records.

**Outcomes:** Historical labels already exist on the server. 'Later' means application-level reveal after immutable prediction persistence, not future data collection. The raw public dataset and seed SQL are available to the developer, so this is an interface leakage boundary rather than a cryptographic blind evaluation. The score endpoint requires a completed prediction matrix. Before that, result responses use only the revealed outcomes table and return null for hidden labels.

**Metrics:** Brier = mean((p-y)^2), lower better. Accuracy uses the run's declared threshold (default .5). Reliability bins are [0,.1), ... [.9,1]. Empty bins remain empty, not zero. No confidence interval is estimated. All metrics are calculated in code; the LLM supplies no counts or aggregate rates. Scores compare the intersection of records valid across every provider; this can be selective when failures are correlated with difficulty, so requested counts, failures and valid coverage are always shown. The full statistical benchmark and a 20-record demo are different cohorts and must not be compared as if identical.

**Latency/cost:** Monotonic elapsed wall time covers adapter calls and retries; excludes queue time and D1 persistence. Median and p95 use linear interpolation over every attempted record, including invalid/error records. Cost per valid result divides all known per-provider costs by valid result count, so known invalid-call costs are included. If any record's cost is unknown, the aggregate stays unknown. Local adapters have zero model API charge, not zero compute cost. Rates are user-configured USD per million input/output tokens for each provider; estimated costs are not invoices. Usage may be missing. After retries, total usage/cost can be incomplete and cost is marked unknown. Failed malformed outer JSON may not preserve token usage. A Workflow replay after an uncheckpointed provider call may repeat an external request; storage is idempotent, paid API execution is not guaranteed exactly once.

**Interpretation:** The title describes a calibration-aware evaluation tool, not a claim that its models are well calibrated. Small LLM samples are exploratory, public historical contamination remains possible, and future marketing performance is unknown. No live-provider benchmark has been executed.
